🏆 LeaderboardHeap (Custom Binary Max-Heap)

                                
Powers the global and contest leaderboards. Extracts the Top-K student competitors in O(K log N) time without sorting all N students.

                            

                            

                                
Insert: O(log N)

                                
Extract Max: O(log N)

                                
Top-K: O(K log N)

                                
Space: O(N) Array

                            

                        


                        
                        

                            

                                
                                
                                
                            

                            

                                
                                
                                
                            

                        


                        
                        

                            
BINARY TREE REPRESENTATION (MAX-HEAP PROPERTY: PARENT >= CHILDREN)

                            

                                
                            


                            
UNDERLYING 0-INDEXED ARRAY BUFFER STORAGE:

                            

                                
                            


                            

                                📐 Index Arithmetic:
                                Parent(i) = ⌊(i - 1) / 2⌋
                                LeftChild(i) = 2i + 1
                                RightChild(i) = 2i + 2
                            

                        


                        

                            💡 Viva Defense Insight: When an examiner asks "Why not just write SELECT * FROM users ORDER BY points DESC or sort the ArrayList?", explain that sorting an array takes O(N log N). For a competition with 50,000 students where we only need the Top-10 winners, the LeaderboardHeap extracts them in O(10 log 50000) ≈ 160 operations instead of 50000 × 16 ≈ 800,000 operations — an incredible 5,000x computational efficiency gain.
                        

                    


                    
                    

                        

                            

                                
⚡ QuickSortRanking (Median-of-Three Partitioning)

                                
Custom sorting implementation with anti-degenerate pivot selection. Guarantees balanced partitions and prevents O(N²) worst-case degradation on pre-sorted arrays.

                            

                            

                                
Average: O(N log N)

                                
Worst-Case: O(N log N)*

                                
Space: O(log N)

                                
Tie-Breaker: Lexicographic

                            

                        


                        

                            

                                
                                
                                
                                
                            

                            Ready to partition array
                        


                        
                        

                            

                                
                            

                            

                                 Normal Element
                                 Median Candidate (Left, Mid, Right)
                                 Chosen Pivot
                                 Partitioned / Sorted
                            

                        


                        

                            💡 Viva Defense Insight: Standard QuickSort picks either the first or last element as pivot. If a student list is already sorted or reverse-sorted, the partition is maximally unbalanced (1 and N-1 elements), causing the call-stack to degrade to O(N²) and potentially crash with a StackOverflowError. Our median-of-three strategy samples arr[low], arr[mid], and arr[high] and picks their median, statistically guaranteeing balanced recursive trees!
                        

                    


                    
                    

                        

                            

                                
🥞 EditorUndoStack (Generic LIFO Array Stack)

                                
Powers the code editor's Ctrl+Z (Undo) and Ctrl+Y (Redo) operations. Implemented with a custom resizable array with O(1) push, pop, and peek operations.

                            

                            

                                
Push: O(1)

                                
Pop: O(1)

                                
Peek: O(1)

                                
Capacity: 2x Resizing

                            

                        


                        

                            

                                
                                
                            

                            

                                
                                
                                
                            

                            

                                Stack Size: 3 / Capacity: 10
                            

                        


                        
                        

                            

                                
                            

                            

                                
TOP POINTER ➔ Index 2

                                
BASE ➔ Index 0 (Bottom of Stack)

                                

                                    When the stack fills its initial capacity (10), it dynamically allocates a new contiguous block of 2 * capacity (20), achieving amortized O(1) push operations without memory fragmentation.
                                

                            

                        

                    


                    
                    

                        

                            

                                
📬 SubmissionQueue (Thread-Safe Concurrent FIFO Buffer)

                                
Buffers incoming student code submissions. Protects CPU and memory by processing compilation requests serially via a background worker thread.

                            

                            

                                
Enqueue: O(1)

                                
Dequeue: O(1)

                                
Threading: Synchronized

                                
Fairness: Strict FIFO

                            

                        


                        

                            

                                
                                
                                
                            

                            

                                 Worker Thread: Active & Ready
                            

                        


                        
                        

                            
                        


                        

                            💡 Viva Defense Insight: During a live coding battle with 100 students submitting code simultaneously, spawning 100 compiler processes at the same instant would exhaust system RAM and freeze the server. The SubmissionQueue guarantees thread-safe decoupling: submissions are enqueued in O(1) time while workers pull from the head in strict FIFO order.
